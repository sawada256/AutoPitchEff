# AutoScaleLink 調推定・連携の調査と設計

調査日: 2026-10-06。製品の公開仕様と公開研究を参照した独自実装。非公開の商用内部処理を再現したという意味ではない。

## 選んだ構成

ライブで重視するのは、音声経路を止めないこと、根拠の少ない調変更をしないこと、GUIを閉じても動くこと。独自の倍音テンプレートによる非負音高推定、音高クラス集約、複数の調プロファイル・スケール内音率、24状態の逐次推定、滞在時間による変更確認を組み合わせる。市販品や最新学習モデルを上回る精度を証明した方式ではない。実録音での比較なしに最高水準の精度を保証できない。

Mixでは左右別のFFTのエネルギーを合成し、逆位相による相殺を避ける。スペクトルピークを半音音高へ投影し、複数倍音のテンプレートを非負座標降下でフィットしてからクロマへ集約する。Vocalでは既存の周期性・倍音を使うPitchDetectorから有声音の音高だけを集約する。両者とも複数秒の観測を必要とする。ミックスのキー候補とボーカルの音域の違いを扱うため、解析モードを明示する。

自動反映は十分な観測時間、複数の音高クラス、候補間の差、信頼度、同じ候補の継続を条件とする。相対長短調で同じ7音を共有する場合には、補正用スケールが同一なのでその差を誤ったスケール変更として扱わない。短調の補正先は既存AutoPitchEffと同じ自然短音階。和声的／旋律的短音階、教会旋法、特殊スケール、個別音階編集は未対応。

調プロファイルはKrumhansl／Temperleyを参考に65:35で組み合わせ、短調の第7音を自然短音階に合わせて変更した独自プロファイル。元研究の数値・成績をそのまま再現するものではない。上位候補と異なる補正用7音スケールの候補との差をScoreに使い、相対調のラベルだけが揺れる場合を区別する。

## 連携

AutoScaleLink → AutoPitchEffの前段配置、またはミックス・伴奏バスのAutoScaleLink → 別のボーカルトラックのAutoPitchEff。macOSの同一ユーザー内共有メモリを使い、同じLink Groupで通信する。音声経路にデータを埋め込まず、音声への追加遅延は0サンプル。重いFFT・調推定と送信者の管理はバックグラウンドスレッド、受信はロック不要のアトミック読み取り。Intel / ARMやホストの別プロセスにも対応する設計。

承認モードを初期設定とし、候補を見てApplyで送る。自動モードは安定候補を継続して反映する。各Groupの送信者は1つ。競合を表示し勝手に上書きしない。同じGroupは同一ユーザーの別DAWにも届くため、別曲では別Groupを選ぶ。受信を明示的にONにするまでは既存の手動Key / Scaleを維持する。送信停止時は最後の適用済みキーを保持し、受信OFFで手動設定へ戻る。

## 限界と検証方針

単音、短いフレーズ、無調、強い打楽器、歪んだ倍音、外音、借用和音、転調直後では曖昧になる。確率校正をしていない信頼度は正解確率ではない。解析待ち時間と音声の追加レイテンシーは別であり、0遅延で曲の調を確定することはできない。合成の既知キー・転調・無音・ノイズ、ステレオ逆位相、承認・自動切替、競合、保存復元、別プロセス連携、VST3バリデーションを検証する。実際のバンド音源での正解率は別途評価が必要。
