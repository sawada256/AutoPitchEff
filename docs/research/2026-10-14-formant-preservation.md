# フォルマント保持ピッチシフト：設計

調査・試作日：2026-10-14。製品資料と論文の調査、合成母音での試作測定にもとづく設計案。実装はまだ行っていない。数値は「資料の記載」「本プロジェクトでの試作測定」「目標値」を区別して書く。

## 1. 結論

**第 1 段階は「LPC による音源・フィルタ分離」で、既存の `PeriodShifter` を包む構成にする。**

1. 入力の声から、その瞬間の声道の響き（スペクトル包絡）を LPC で推定する。
2. 入力を LPC 逆フィルタに通して響きを取り除き、平坦な「音源（残差）」にする。
3. 残差だけを既存の `PeriodShifter` で音程変換する。
4. 変換後の残差に、元の響きを LPC 合成フィルタで付け直す。

この構成を選ぶ理由：

- **追加の遅延がない。** 固定遅延（8 サンプル）も、音程に応じて変わる動的遅延も、今と同じ。音程変換部は変えず、その前後にフィルタを足すだけ。
- 読み出し位置の安全性、ステレオ連動、検出系など、検証済みの部分をそのまま使える。
- 試作では、F0 440 Hz 以下での包絡誤差が 9〜18 dB から 1.8〜3.3 dB に下がった（§4）。条件をそろえた理想的な TD-PSOLA と同等以上。
- 弱点は高い声（F0 660 Hz 付近）。誤差は 1.8〜8.0 dB に留まる。第 2 段階で、F0 を使った包絡推定に置き換えて改善する（§5.2）。

TD-PSOLA は比較対象として残す。第 2 段階の後、実際の歌声で比べて優れていれば第 3 段階で採用を検討する（§5.3）。

## 3. 方式の比較

| 方式 | フォルマント | 追加遅延 | 課題 | 判断 |
|---|---|---|---|---|
| 現在：再生速度変換＋周期つなぎ | 音程と一緒に動く | 0 | 大きく変えると子供っぽい声・太い声になる | 現状 |
| **A. LPC 音源・フィルタ分離＋既存シフター** | 保持（推定包絡の精度しだい） | **0** | 高い F0 では LPC が倍音に引っ張られる | **第 1 段階で採用** |
| B. TD-PSOLA（Moulines & Charpentier 1990 [4]。Lent 1989 [5] も周期同期で包絡を保つ） | 原理的に保持 | 約 1 入力周期（180 Hz で 5.6 ms） | 正確な周期マーク（声門閉鎖時刻）が必要。雑音に弱い | 第 3 段階で比較 |
| C. 位相ボコーダ＋包絡補正（Lenarczyk 2017 [6]、True Envelope [7]） | 保持 | 窓長の分（20〜60 ms） | ライブには遅延が大きすぎる | 不採用 |
| D. ニューラル（RT-PAD-VC [8]、iZotope [3]、拡散モデルによる修復 [9]） | 保持・音色変換まで可能 | 数十 ms 以上、CPU 負荷大 | ライブ・低遅延に合わない。検証も難しい | 不採用（オフライン用途なら将来検討） |

## 4. 試作測定（本プロジェクト）

再現用のソースは [`formant-prototype/`](formant-prototype/) に置いた。

**条件**
- 包絡が既知の合成母音：/a/ 風のフォルマント 850 / 1220 / 2810 / 3800 Hz、−6 dB/oct の傾き、−60 dB の下限。
- 48 kHz、定常音、F0 は 220 / 330 / 440 / 660 Hz、変換量は ±7・±12 半音。
- 誤差の定義：出力の各倍音の振幅を、理想値（変換後の倍音周波数における元の包絡の値）と比べる。範囲は 200〜4500 Hz。全体の音量差を除いた RMS を dB で表す。小さいほど良い。

**結果（dB）**

| F0 | 変換 | 現在（補正なし） | A. LPC（40 次、1024 点窓、64 サンプルごと） | B. 理想 TD-PSOLA（正確な周期マーク、2 周期 Hann 窓） |
|---|---|---|---|---|
| 220 | −12 / −7 / +7 / +12 | 12.2 / 9.7 / 10.0 / 15.4 | 2.4 / 2.4 / 1.9 / 1.8 | 3.7 / 2.7 / 3.2 / (0.0)* |
| 330 | 同上 | 11.7 / 8.9 / 9.5 / 13.4 | 3.3 / 2.9 / 2.2 / 2.0 | 5.2 / 3.7 / 3.1 / (0.1)* |
| 440 | 同上 | 12.5 / 10.1 / 9.7 / 17.7 | 2.9 / 3.2 / 2.0 / 2.0 | 4.0 / 5.9 / 2.5 / (0.1)* |
| 660 | 同上 | 10.9 / 8.6 / 12.1 / 10.1 | 5.8 / 7.3 / 8.0 / 1.8 | 5.7 / 6.0 / 4.9 / (0.1)* |

\* 定常音をちょうど 1 オクターブ上げる場合、PSOLA の出力倍音は元の倍音の一部と一致するので、自明に誤差 0 になる。比較には使わない。

**わかったこと**
- LPC の次数は 40（48 kHz）が 24 より良い。F0 に応じたラグ窓による平滑化は、どの条件でも悪化した。
- F0 660 Hz では倍音の間隔が広く、LPC が倍音の山に合わせてしまう。下方向や +7 の変換で誤差が 6〜8 dB 残る。
- 理想 PSOLA は 660 Hz でやや優れる（4.9〜6.0 dB）。ただし実際の音では周期マークの誤差が加わるため、これは上限側の値。

**限界**：結果は定常の合成音によるもの。母音の移り変わり、ビブラート、子音、息成分、実際の声の非周期成分は含まない。実際の歌声での評価は §6 で行う。

## 5. 設計

### 5.1 第 1 段階：LPC 包絡の補正（遅延ゼロ）

```
main（位置合わせ後）─┬─ 分析 LPC（過去のみ） → 反射係数のフレーム履歴
                     │                            │（読み出し位置に対応するフレームを使う）
                     └─ 逆フィルタ A(z) → 残差 → PeriodShifter → 合成フィルタ 1/A(z) → wet
dry ─────────────────────────────────────────────────────────────→ Dry/Wet ミックス
```

- **分析**：音程変換される main 音声（位置合わせ遅延の後）で行う。サイドチェイン検出モードでも、包絡は加工対象の main から取る。ステレオでは、検出用ソースの設定（和 / L / R）に従った 1 系統で推定し、同じフィルタを両チャンネルに使う。これで左右のバランス（パン）と連動が保たれる。
- **パラメータ**：次数は 48 kHz で 40（サンプルレートに比例させ、上限 64）。窓は Hann、約 21 ms、過去のサンプルだけを使う。更新は約 1.3 ms ごと（48 kHz で 64 サンプル）。安定性のため、自己相関の 0 次に 1.0001 倍の白色雑音補正を加え、帯域拡張係数 γ = 0.995^k を掛ける。Levinson–Durbin 法で反射係数を求める。
- **フィルタの構造**：分析・合成ともに格子型（ラティス）にする。反射係数をサンプルごとに補間しても、|k| < 1 が保たれるので必ず安定する。
- **時刻合わせ**：シフターは残差を d(n) サンプル前から読み出す。そのため、出力時刻 n の合成には、時刻 n − d(n) に推定したフレームを使う（フレーム履歴は約 100 ms 分のリングバッファ）。二つの読み出し位置をクロスフェードしている間は、重みで平均した d を使う。こうすると、母音が変わるときの包絡の動きが音声と時間的にずれない。
- **無変換時の性質**：変換比 1（遅延 8 サンプル一定）のとき、分析と合成が同じ時刻の同じ係数を使うので、理論上は元の音に完全に戻る。これを回帰テストにする。
- **CPU の見積り**：自己相関に約 1024 × 41 回の積和を 64 サンプルごと、フィルタに 1 サンプルあたり 2 × 40 × チャンネル数。合わせて 48 kHz ステレオで毎秒約 4,000 万回の積和と計算される（自己相関が約 3,100 万、フィルタが約 770 万）。FFT で自己相関を求めればさらに減らせる。M4 で問題ない見込みだが、`ape_dsp_tests` の CPU 計測で確認する。オーディオ処理中のメモリ確保はしない（バッファは prepare で確保）。
- **UI**：`Formant` を `Off / Preserve` で切り替える（Waves の Corrected / Non-Corrected に相当）。既定は Off にして、既存のセッションの音を変えない。評価の後で既定を Preserve にするか判断する。

### 5.2 第 2 段階：高い声向けの包絡推定

高い F0 で LPC が倍音に引っ張られる問題への対策として、**F0 を使った包絡推定**に切り替える。

- 候補 1：True Envelope 法 [7]。ケプストラムを反復して倍音の山を結ぶ包絡を求める。次数は F0 から決める。得た包絡のパワーを逆 FFT して自己相関にし、Levinson で LPC 係数に変換する。フィルタ構造は第 1 段階のものをそのまま使う。
- 候補 2：離散全極モデル（Discrete All-Pole、El-Jaroudi & Makhoul 1991）。倍音の周波数の点だけに全極モデルを合わせる。
- F0 は既存の検出器の値を使う。F0 が不明なとき（子音・息）は第 1 段階の LPC に戻す。
- 目標（試作で確認）：F0 660〜880 Hz で、±12 半音までの包絡誤差を 4 dB 以下にする。

### 5.3 第 3 段階（必要なら）：TD-PSOLA との比較

第 2 段階の後、実際の歌声で TD-PSOLA（周期マークは既存の周期照合 `matchPeriod` を流用）と比較する。採用するのは、遅延が約 1 周期増えることを許容できるほど音質が明らかに良い場合だけ。

### 5.4 拡張：フォルマントを意図的にずらす

合成側で包絡の周波数軸を伸縮すると、コーラスの声質を変える操作になる（Auto-Tune の Throat に相当）。方法は、係数の周波数伸縮（全域通過フィルタによる warped LPC）か、§5.2 の包絡を伸縮してから LPC に変換するか。±12 半音を想定。コーラス生成で、主旋律と声質を変えて厚みを出すのに使える。

## 7. リスク

- 実際の声では、鼻音や息成分が多い部分で LPC 包絡が乱れ、残差に雑音が乗ることがある。その場合の対策は二つ：信頼度（周期性）が低いときは補正を弱める、分析窓を長くする（遅延には影響しない）。
- 包絡フレームの時刻合わせを誤ると、母音の変わり目で響きが前後にずれて聞こえる。§5.1 の読み出し位置連動で対処し、母音が切り替わる合成音のテストを用意する。
- 下方向に大きく変換すると、残差の高域が空になる（再生速度を下げるため）。合成フィルタは響きを付けるだけなので、高域の空気感が減る。必要なら残差に高域雑音を少し補う（第 2 段階で検討）。

## 8. 実装結果（2026-10-14）

第 1 段階（LPC）と第 2 段階（True Envelope）を両方実装し、Formant メニューで選べるようにした。両者を F0 で切り替える Auto も加えた。実装は `Source/dsp/Formant.cpp`。

**True Envelope の調整**：推定した包絡そのものを、真の包絡と比べて測った（200〜4500 Hz を 25 Hz 間隔、括弧内はフォルマントの山付近）。最初の設定（反復 6 回、下限 −100 dB、次数 0.5·sr/F0）は、F0 330〜440 Hz で LPC より悪かった。下限を −60 dB、反復を 12 回、次数を 0.6·sr/F0 に変えると、すべての F0 で LPC と同等以上になった。

| F0 (Hz) | 196 | 220 | 330 | 440 | 550 | 660 | 880 |
|---|---|---|---|---|---|---|---|
| LPC | 2.3 (1.9) | 2.4 (1.8) | 2.9 (3.1) | 3.3 (3.2) | 5.5 (5.1) | 7.9 (7.5) | 6.6 (4.1) |
| True Envelope | 2.2 (2.0) | 2.8 (2.6) | 3.3 (4.0) | 3.3 (3.3) | 3.8 (2.8) | 4.0 (3.5) | 5.3 (3.7) |

**エンジン全体の包絡誤差**（§4 と同じ方法、±3・±7・±12 半音、dB）：

| F0 | Off | LPC | True Envelope |
|---|---|---|---|
| 220〜440 Hz | 5.1〜17.7 | 1.7〜4.6 | 2.7〜4.9 |
| 660〜880 Hz | 1.7〜14.0 | 2.5〜6.7 | 1.3〜5.5 |

この結果から、Auto の切り替え点を 500 Hz にした。

**音量**：包絡を新しい倍音の位置で読み直すため、出力の音量は −16 dB〜+8 dB 変わった（LPC の高い F0 で最大）。iZotope の正規化項 κ [3] と同じ目的で、wet の音量を入力に約 30 ms で合わせる処理（±12 dB まで）を加えた。これで合成母音での変化は 0 dB（LPC 660 Hz +7 半音のみ −3.7 dB で、補正の上限に達している）。

**CPU**（M4、48 kHz、モノラル、1 秒の音声あたりの処理時間）：Off 0.023 s、LPC 0.033 s、True Envelope 0.086 s。Auto でステレオ処理した場合は 0.060 s。

**コーラス用パラメータ**：Detune、Humanize（約 250 ms ごとに目標を変える、決定的な乱数による揺れ）、Double delay（wet のみの遅延）。正確さ・決定性・メモリ確保がないことを `ape_dsp_tests` で確認している。

**未確認**：実際の歌声での評価（§6 の vocadito 評価と聴感確認）はまだ行っていない。
